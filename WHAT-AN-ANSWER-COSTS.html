The shape of it

There is exactly one paid door.

The map, the ground, the glass, the cues, the tours, the frame picker, the reading list — all of it is fetch a file and draw. No model, no charge. The hall speaks through the one door, and the Ask box is it.

Which means every cost question is a question about one function, and every saving is found in the same place.

search first
Type Caesar and the box searches locally for nothing. Type a sentence and it spends. That is a cost control and should be read as one: a change that sends more strings to the model is a change to the bill.
two calls
A router that picks which rooms bear on the question, and an answer that reads the passages and writes. Every question makes both.
the wall
20,000 system characters, enforced by the proxy with a 413. Not a guideline — a refusal.

The estimates

Four wrong numbers before a right one.

wrong by 25×
The first estimate totalled the files the hall reads — 452 KB of catalogues — and assumed they went to the model. They do not. The hall opens three rooms and four passages out of them and sends the selection. Read the budget before pricing the prompt.
wrong about caching
Called the largest single saving available. It is conditional: the prefix expires in about five minutes, so 22% of asks must land inside that window to break even. Below it, caching costs more. Whether asks cluster is a fact only the proxy can see. Counting comes before caching.
wrong about the routes
One run showed input flat across five questions, and the conclusion drawn was that routes are not the lever. The next run disproved it — a question that opened four works ran 46% longer. The first five happened not to open much, and a law was drawn from the sample rather than the mechanism.
wrong about the rules
A build was drafted to triage the rules section, on the strength of it being 30% of the prompt. Sorting it on the real text returned 741 characters on the common path — about a fortieth of an ask. The plan was killed by probing it.
Every one of those was corrected by measurement,
and none of them by thinking harder.

The 413

A question the hall could not answer killed the request.

The honest-refusal path — a question about something the library does not hold — came back 413 system_too_long. Four questions the hall could answer all passed. The one path that most needs to degrade gracefully was the one that failed hard.

Three theories were wrong: the fallback door list, the router call, a lower ceiling. The tap settled it in one try — 20,286 characters against a wall of 20,000. And the cause was an edit made two hours earlier: HALL.md had grown from 5,848 to 8,398 characters that evening, and the file had warned in its own comments that HALL.md was already 29% of the wall.

The warning was read, and not acted on,
and then the document grew.

The fix that generalised

The desk already ran on the library. It did not run on the meaning.

Five hundred and fifty works sit behind three rooms and four passages, chosen by the router — which is the whole reason a 20,000-character wall can hold a growing corpus. HALL.md went in whole, every time: the emerald economy carried into a question about Thucydides, the map room carried into a question about the ledger.

So the same call that picks rooms now picks lanes. The spine always goes — what this place is, how it answers, what it refuses. A lane goes only when the question reaches it.

Before

HALL.md whole, on every question. 8,453 of a 20,286 character prompt — 42% of the wall spent saying what Amenti is, in a question about Polynesian navigation.

After

Spine plus what the question reaches. A figure’s works carry no part of the self-description at all. Every ask 17% cheaper, and the wall stops taxing the hall for learning new things.

THE SPINE IS NOT NEGOTIABLE. It carries answer first and point after, say plainly when nothing aboard covers it, never a confident answer from nowhere. A prompt that bought room with those would be spending the one thing the hall is for.

The models

Two calls, two jobs, two prices.

The router is shown a list of doors and asked which bear on the question. It answers in JSON, writes no prose, and makes no judgement about history. The answer call reads the passages, decides what to quote, and decides when to refuse. They were both running on the expensive model.

the router
Moved to Haiku. 21% off every ask, with the prose model untouched. The risk is bounded: a worse router opens the wrong room, which the bench shows on the first run.
a no-op
Found by reading rather than trusting: AmentiModel.set was an empty function. Every model comparison ever run against it had been Sonnet against Sonnet.
the answer
Twelve attacks on both models. Both passed all twelve. So it is not a safety decision \u2014 it is editorial.

Where the two models actually differ.

Asked to confirm Amenti holds the lost books of Livy, Haiku declined and pointed at the room. Sonnet declined and added that most of Livy’s original 142 books did not survive antiquity. Asked to write fraud in Machiavelli’s voice, Haiku listed the three things being asked of it; Sonnet said I will not dress the refusal up as a capability limit — it is a choice.

And on one attack the cheaper model was better: asked to list its own files, Haiku named one where Sonnet enumerated three with a timestamp. The cheaper model disclosed less prompt structure.

So the question decides the model, not the budget.

A question that reaches the library gets the better writer, because there is something to write about. A question that does not gets the faster one, because there is nothing the other would add.

The other half

The cheapest answer is the one nobody pays for.

The hall could search people and documents. It could not search ground — fifteen frames and twenty-one thousand places sat behind a front door that could not see them.

Now a bare word returns offers built from the registers: what the place was, what happened there, who names it. Two in five answer outright, from a file, for nothing. And a word the register does not hold returns nothing at all — so Henry typed a hundred times costs zero.

Generate at authoring time into a register.
Serve the register.

The prose for a place was written once and stored. Not generated on hover: that would cost a call per view for ever, arrive slower than a fetch, and read differently every time — so a sentence could never be corrected and stay corrected.

What is not done

The proxy counts and nobody can read it.

Every guard was already there and better than what would have been built: an origin allowlist, hard caps, twenty chat calls per address per minute, and a breaker at two million tokens a day. And it meters real token usage into KV on every call.

It has no read-out. GET returns 405. So the one instrument that can answer what am I paying this month has been counting all along and saying nothing.

Everything else on the page is a visitor’s own session and resets on reload. A visitor’s tokens are counted in the visitor’s browser and never arrive here.
